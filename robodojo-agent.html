任务分数能解释多少失败？

我回看了 RoboProbe 的 RoboDojo 轨迹，并核对任务说明、工具接口和原生评分源码。在整理的 42 项不同任务笔记里，24 项提及抓取或抓持稳定性，20 项提及精细对齐或接触调整，7 项提及画面、模型自判与系统验收不一致。标签允许重叠，分母是任务笔记数量。这份分类帮助我选出值得复跑的接触失败。

按键案例 · 先区分意图、触发和验收

按数字按键（press_by_number）的简版指令容易读成“两颗红键都按完，再按蓝键确认”。详细指令和评分源码明确了两次确认：第一颗红键按够次数、蓝键确认、第二颗红键按够次数、蓝键再确认，最后双臂归位。比较模型对操作顺序的理解时，应先统一它们收到的指令版本。

  1. 任务理解：核对模型读到的两张数字卡、按钮对应关系和两次确认的顺序。
  2. 接触执行：将末端轨迹与按钮关节行程对齐。评分逐次检查归一化关节位置小于 0.5 和释放后大于 0.9，并限制按压次数。
  3. 评分判定：分别记录按压／释放事件、顺序与归位。画面里接触了按钮，仍需要事件日志确认是否计为有效按压。

我会保留原生分数，并附上逐阶段事件、通过条件和失败回放。比较系统时统一指令、观测权限与控制步预算，同时单独报告模型响应数和墙钟耗时。总分相同的两次运行也可以有不同的失败原因。

让模型决定目标，让执行器处理反馈

我实现了 Robot Use Agent 的模型接口、RoboDojo 适配器和执行回执。直接工具控制的基线由大模型逐轮看图和发位姿、夹爪指令，再等待执行结果。改进后，模型保留高层选择和重规划，执行器将动作转换为本体命令，并在局部阶段处理比模型响应更快的反馈。

动作接口与回执

统一夹爪开口单位，区分移动中调整和到位后闭合。回执记录位姿误差、实测开口、停滞和终止原因。模型可以根据下一帧图像决定是否抬升、换姿态或重抓。

持续工具循环

模型在同一会话中调用观察、执行和结束工具。执行工具一次返回新观测和回执；原生评分与模型判断独立保存，便于核对是否真正完成。

完整任务的历史运行同时变更了多项因素。我另选了四段已失败的 RoboDojo / PhysX 接触轨迹，重放到同一物理状态，固定目标孔、右臂与时间预算，由左臂接管。两种闭环控制器根据 RGB 估计管尖和管轴再纠偏，视觉丢失时暂停修正。第三组在同一视觉输入上增加短时运动预测，用于检查世界模型是否有额外收益。

每种方法另做了 20 次无外加微扰的原样复跑，固定轨迹 5/20，另外两组各 10/20。两部分合计 204 次仿真。每条分支执行 99 个控制步（3.96 秒仿真时间），成功要求撤手后最后连续 8 步都满足指定孔位、插入深度超过 45 mm、管轴偏离竖直不超过 30°等条件。控制器读取 RGB 和本体状态，仿真真值用于选片、核对与判分。

改善来自指间滑动。这一状态的微扰试次里，闭环把撤手后管尖深度中位数从 16.7 mm 提高到 54.0 mm。四个起点合计提升 22.9 个百分点，固定起点内的配对 bootstrap 95% 区间为 18.8–25.0 个百分点。该区间描述所选接管状态下的局部恢复，完整插管任务仍需端到端验证。

哪些失败需要不同的处理？

  • 倾倒：持续提供准确的仿真管姿时，原先失败的两个闭环控制器均救回 2/2。仅校准首帧仍为 0/2，说明这段轨迹需要持续可靠的管姿观测。
  • 卡住：逐步给准确管姿、再把纠偏时长翻倍，两种方法仍各为 0/2。控制指令与关节实测继续分离，后续应优先检查受阻时的实际关节反馈和卸载策略。
  • 短时预测：当前世界模型辅助与视觉伺服在全部 48 组配对微扰中成败相同。在这组状态上，简单几何闭环已经覆盖了观测到的收益。
